# Phase 4 Known Limitations

- Extraction is an explicit local CLI operation. There is no FastAPI endpoint, frontend review screen, ingestion hook, cancellation control, or automatic retry. This keeps Phase 1 and normal ingestion independent.
- The adapter consumes current normalized page text, which has already had whitespace cleanup, line-break dehyphenation, and repeated-header/footer removal in some loaders. Offsets are exact only against this normalized representation, not the original bytes or PDF visual layout.
- Title/authors/year/DOI come from current parser metadata. Author affiliations, submission dates, venues, keywords, and language are not reliably discovered if absent from that metadata or explicit text patterns. Language remains `unknown`.
- Heading recognition is deliberately conservative but still heuristic. Roman-numbered headings, two-column reading order, OCR artifacts, unnumbered bold headings, and domain-specific section names may be missed or misclassified. Unknown headings require review.
- Knowledge extraction matches deterministic phrases. It can miss implicit statements and can surface irrelevant sentences. Confidence is a rule signal, not calibrated probability or semantic support. Claim/finding candidates are not verified scientific conclusions.
- The shared loaders flatten many DOCX/PPTX/CSV/XLSX tables. Table rows, columns, units, footnotes, and cell positions cannot be reconstructed from that flattened output. PDF table structure is not exposed by the current loader.
- Figure images and visual descriptions are not extracted. Some textual caption-shaped lines are identified, but caption associations and nearby paragraphs are not guaranteed.
- DOCX OMML equations are supported by the existing converter, but page/character position, equation number, and nearby explanation are unavailable. Converter output is searchable LaTeX, not guaranteed typographically exact. PDF equation layout is not recovered.
- OCR is unavailable. Image-only PDFs produce a visible `needs_ocr` artifact. Mixed PDFs with some text and some image-only pages are marked partial, but the parser cannot identify every image-only region reliably.
- Reference parsing is conservative and format-dependent. Author/title/year parsing can be incomplete; citation matching only links numeric markers to numbered bibliography entries. Author-year citation linking and bibliography verification are not implemented. A DOI/URL is never proof of authenticity or scientific reliability.
- Local JSON snapshots store normalized page text to support provenance validation, which duplicates parser output locally. The directory is ignored by Git but relies on the user's local filesystem access controls and backup practices. Concurrent multi-process review writes are not coordinated.
- Review state and corrections are local event overlays, not a team workflow. The optional training-permission flag is recorded on review events, but Phase 4 intentionally provides no training export and does not auto-create labels.
- No real-document quality scores, target-machine memory figures, or representative speed claims are available. The full test suite runtime is not a Phase 4 extraction benchmark.
- Permanent knowledge graphs, graph traversal/visualization, external verification calls, OCR integration, automatic model activation, and training on extracted records remain outside Phase 4.
