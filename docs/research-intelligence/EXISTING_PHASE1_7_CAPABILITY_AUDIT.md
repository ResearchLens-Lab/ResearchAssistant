# ResearchLens Phases 1–7 Capability Audit

**Audit basis:** source inspection of the current checkout on 2026-11-13. Earlier status reports were treated as pointers only. This is a code-path audit, not a claim that every path passed an end-to-end run. Tests were not run as part of this audit.

## Executive finding

ResearchLens already has a substantive deterministic document-QA path. The defaults in `rag/config/settings.py` and `backend/app/core/config.py` select `rag_engine_mode="independent"`; `backend/app/integrations/rag_client.py` then routes ingestion, querying and index counts to the SQLite FTS5 implementation in `rag/independent/`. This path does not construct an embedding model or a response generator. It does not mean every research subsystem is part of that path.

The most important integration gaps are: Phase 4 document intelligence is a CLI/separate JSON artifact rather than part of upload indexing; Phase 2/3 reviewed training has no authenticated product feedback-to-dataset bridge; the default independent question path bypasses the richer Phase 7 planner/orchestrator; and there are two graph boundaries, one SQL-backed backend graph API and a separate Neo4j service whose backend client currently reports unavailable. Phase 6 memory is opt-in and separate from normal answer retrieval.

## Document and provenance facts

- Supported loaders currently include PDF, DOCX, TXT/Markdown/TeX, CSV, XLSX, PPTX, JSON and HTML (subject to optional parser packages). PDF extraction preserves one-based physical PDF page numbers; no printed-page mapping model was found in standard chunk metadata.
- `ChunkMetadata` carries `owner_id`, `paper_id`, `document_id`, page range, section, title, filename, locator and extra data. It does not include immutable document-version ID, parent paragraph/table-cell IDs, source offsets, parser version or extraction confidence.
- `backend/app/models/paper.py` is the project container (title/description/metadata); `Document` is the uploaded file. Do not treat project title as a verified document title.
- `DocumentIntelligence` has useful page/block/section/knowledge/reference/equation structures, but omits first-class table rows/cells, figures, paragraph/sentence parents and document-version lineage. Several extracted records are explicitly heuristic/low confidence.

## Privacy, external calls and runtime boundaries

- The default independent index is local SQLite FTS5 and the default upload storage path is local `./storage/uploads`; backend DB default is a local PostgreSQL service at `localhost`. This is local deployment, not OS-account isolation or encrypted-at-rest proof.
- The RAG settings still define optional FastEmbed/Gemini embeddings and optional Ollama/other generation providers. The default independent path does not need them, but configuration can select legacy/model paths. `ResearchIntelligenceService.PublicMetadataProvider` has explicit HTTP lookup behavior (Crossref/OpenAlex). Treat this as an external network feature, not a local-only operation; it must be separately consented and disclose sent query metadata.
- The knowledge-graph URL is configurable; the checked-in backend client currently raises unavailable rather than forwarding graph data. Do not infer network behavior from the presence of the Neo4j package alone.
- No blanket claim of encryption, offline guarantees, OS-user separation, automatic backup/restore, or zero outbound traffic is supported by this audit.

## Evaluation and training data quality

- `rag/evaluation/phase1_independent_dataset.json` declares its cases hand-authored against synthetic passages. It is useful for deterministic regression coverage, not a golden set based on authorized user papers.
- `rag/evaluation/datasets/research_intelligence_questions.json` and phase2/phase3 fixtures exist. Their presence is not evidence of human-reviewed source labels; inspect provenance before using them as deployment gates.
- `rag/evaluation/metrics.py` includes retrieval/source/citation checks, but keyword overlap and citation-ID existence do not establish semantic claim support. The reviewed training schema/readiness/splits are stronger than the currently observed answer-feedback integration.

## Implementation plan from the observed gaps

1. **Foundation and contract:** define one owner-scoped document-version/provenance contract. Additive schema only after a migration design and legacy-data rehearsal; never delete or rebuild Chroma/FTS indexes.
2. **Document understanding:** run the existing extractor only inside a per-owner, per-document ingestion job; persist run/version/status under the document boundary; preserve page/block offsets and errors. Keep OCR opt-in and explicit. Add table structure only where parsers actually expose it.
3. **Incremental index consistency:** fingerprint bytes, identify exact duplicates within an owner, and index only changed documents. Keep current stable document ID and record extraction/chunk/parser versions. Add crash-safe reindex/rollback and tests against isolated SQLite stores.
4. **Retrieval integration:** add document/section-aware candidate fusion and duplicate/header controls behind a feature flag; preserve the current independent baseline. No trained reranker until reviewed relevance judgments meet document-held-out readiness thresholds.
5. **Answer/evidence policy:** align deterministic composer output to explicit intent and selected format; report lexical validation honestly and abstain when source support cannot be checked.
6. **Feedback and learning:** add an authenticated, owner-scoped review queue with explicit opt-in; export only reviewed, permitted examples into the existing immutable dataset store. Never auto-train from ordinary feedback.
7. **Graph/memory:** document and test one active graph boundary; use only approved, current graph assertions and evidence. Keep memory opt-in and prove ownership at every read/write.
8. **Evaluation/privacy/performance gates:** build a user-authorized human-reviewed golden set; measure retrieval, answer/citation, security and latency; audit outbound calls; establish low-resource limits and backup/restore semantics before calling the system local-private production-ready.

## Audit limitations

This inspection traced the main source modules, route/service seams and named tests. It did not execute upload/query scenarios, inspect user documents, run the complete test matrix, or verify a packaged desktop deployment. All runtime claims above are scoped to static code paths and declared defaults.
