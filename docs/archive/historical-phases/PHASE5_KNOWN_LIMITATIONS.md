# Phase 5 Known Limitations

- The graph schema migration has only been applied to an isolated temporary SQLite database in this task. The configured application database was left untouched; apply Alembic revision `0005` before using graph endpoints/CLI against it.
- No real document has a Phase 5 import yet. The graph remains empty until the owner explicitly imports a current Phase 4 run and reviews its candidates.
- Phase 4 currently emits research knowledge sentence candidates, not trained entity spans or reviewed subject-predicate-object relationships. A reviewer therefore has to identify the intended entity type/name and manually supply edge endpoints and predicate. The graph does not infer these from co-occurrence.
- Phase 4 bibliography records are parsed but not reviewed knowledge records, and `parsed_unverified` entries are not automatically promoted to `PAPER` or `REFERENCE_MENTION` nodes. No DOI/network verification occurs here.
- API and CLI cover authenticated/owner-scoped import, review, evidence, identity, query, and audit operations. There is no graph frontend/visualization; that is deferred to Phase 8. The CLI is a trusted local operator interface and uses an explicit `--owner-id`; API routes provide token-based user authentication.
- Custom ontology extensions are local JSON configuration for the service/CLI. They are not centrally versioned or exposed as a mutable ontology-management API.
- Fuzzy identity suggestions use normalized strings and Python sequence similarity. They are candidates only; acronym expansion, person disambiguation, version-aware entity resolution, and automatic merge are not implemented.
- Identity merge and undo preserve and validate known edge/evidence/alias mappings. There is no concurrent merge lock or team review conflict-resolution protocol. Run graph mutations transactionally and avoid concurrent administrative merges.
- The audit detects duplicate normalized identities, invalid edge endpoint types, orphan/missing evidence, source/reference and offset problems, private classification mismatches, invalid/duplicate aliases, unreviewed graph support, conflicts, and import history. It is read-only and deliberately does not repair data. Very large conflict result sets are capped.
- Source evidence snippets are retained in graph evidence rows to support review and can outlive a library deletion in storage. Queries hide evidence whose document is missing/unowned, and audit flags it; deleting source files does not automatically erase graph history. Use application retention/privacy policy before importing especially sensitive records.
- Graph evidence is valid only while its Phase 4 run remains the current successful run and its review state remains approved. A newer extraction run temporarily makes earlier evidence inactive until the current run is explicitly imported and reviewed; this conservative rule can require re-review after a parser-version-only change.
- Current active-query checks read Phase 4 review artifacts locally. They do not call external services, but missing/corrupt local artifact files make the dependent assertion unavailable and visible to audit.
- No graph-scale memory/latency benchmark or real data quality metric is available. Synthetic tests verify code paths only.
- Associative/temporal memory, automatic multi-hop answering, graph UI, model activation/training, scientific truth verification, and memory consolidation/decay remain deferred to later phases.
